hl7-practice 05: get_value(message, path) -> str

Medium

Return the value in an HL7 v2 message at the given path.

Path format: SEG-F, SEG-F.C, or SEG-F.C.S - SEG: 3-letter segment name (MSH, PID, OBX...) - F: field number (1-based) - C: component number (1-based), split by ^ - S: subcomponent number (1-based), split by &

Rules: 1. Segments are separated by \r, \n, or \r\n (real files often get their line endings converted). 2. If a segment appears more than once (e.g. several OBX), use the first one. 3. If a field has repeats (~), use the first repeat. 4. MSH is special: MSH-1 = | (the separator itself), MSH-2 = ^~\& (returned as-is, not split). So MSH-n (n ≥ 3) is off by one compared with other segments. 5. Not found (missing segment, field/component/subcomponent out of range, or empty) → return "". 6. Separators are fixed: | ^ ~ \ & (no need to read them from MSH-2 yet).

MSH|^~\&|LAB|HOSP|EMR|HOSP|202611110930||ORU^R01|MSG42|P|2.5.1
PID|1||12345^^^HOSP^MR||NGUYEN&VAN^AN^B||19900515|F|||12 LE LOI^^HUE^^530000^VN||(234)555-0101~(234)555-0202
path output
PID-5.2 AN
PID-5.1.1 NGUYEN
PID-13 (234)555-0101
MSH-9.2 R01
PID-4 ""

Follow-up (optional): - Support a repeat index: PID-13[2] → (234)555-0202. - Read separators from MSH-2 instead of hardcoding them. - set_value(message, path, value): that is problem 09.

Write it in p05_get_value.py, then run python3 test_practice.py p05.

Reference solution 
def get_value(message: str, path: str) -> str:
    seg_name, _, rest = path.partition("-")
    field_num, *sub_nums = (int(n) for n in rest.split("."))

    for line in message.splitlines():  # handles \r, \n, \r\n
        fields = line.split("|")
        if fields[0] != seg_name:
            continue

        if seg_name == "MSH":
            if field_num == 1:
                return "|"
            if field_num == 2:
                return fields[1]
            index = field_num - 1  # MSH-1 is the separator itself, so everything shifts by one
        else:
            index = field_num

        if index >= len(fields):
            return ""
        value = fields[index].split("~")[0]

        for sep, n in zip("^&", sub_nums):
            parts = value.split(sep)
            if n > len(parts):
                return ""
            value = parts[n - 1]
        return value

    return ""

Reference solution 
def abnormal_results(message: str) -> list[str]:
    results = []
    for line in message.splitlines():
        obx = line.split("|")
        if obx[0] != "OBX":
            continue
        obx += [""] * (9 - len(obx))  # pad so OBX-3..OBX-8 always exist
        flag = obx[8]
        if flag in ("", "N"):
            continue
        name = (obx[3].split("^") + [""])[1]
        results.append(f"{name} {obx[5]} {obx[6]} ({flag})")
    return results

mellp 08: Peel the Onion

Medium · parsing · delimiters · escapes · stdlib

Libraries hide the HL7 encoding rules until a message arrives that they handle differently from what you expected, and then you need to know what the rules are. This is the one problem where you write the parser by hand: use no HL7 library here, the standard library only. An HL7 message is an onion of five delimiters, and the message itself says which characters they are.

def get(raw: str, path: str) -> str

MSH|^~\&|... declares the delimiters: characters 4 to 8 of the message are the field separator |, then the component separator ^, the repetition separator ~, the escape character \ and the subcomponent separator &. A path has the form SEG[n]-F[r].C.S, numbers 1-based, the bracket and dot parts optional:

  1. SEG is the segment name, [n] the n-th segment with that name (default 1).
  2. F is the field. In MSH, MSH-1 is the field separator character itself and MSH-2 the four encoding characters; return both verbatim.
  3. [r] is the repetition (default 1, so PID-3 means the first repetition of PID-3), .C the component, .S the subcomponent.
  4. Read the five delimiters from the message itself. Do not hard-code them.
  5. Return the text at the level the path names, with deeper delimiters left in place: PID-5 gives DOE^JANE^Q.
  6. Decode escape sequences in the result: \F\ field separator, \S\ component separator, \T\ subcomponent separator, \R\ repetition separator, \E\ escape character. Decode in one left-to-right pass, so \E\T\ becomes \T\, not &.
  7. Anything absent or empty gives "".

Example 1:

raw = ("MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ORU^R01^ORU_R01|MSG00003|P|2.5\r"
       "PID|1||12345^^^HOSP&1.2.3.4.5&ISO^MR~987654321^^^SSA^SS||JOHNSON\\T\\JOHNSON^PAT\r"
       "OBX|1|NM|2345-7^Glucose^LN||182|mg/dL\r"
       "OBX|2|NM|2160-0^Creatinine^LN||0.9|mg/dL\r")

get(raw, "PID-3[2].1")   -> "987654321"
get(raw, "PID-3.4.1")    -> "HOSP"
get(raw, "PID-3")        -> "12345^^^HOSP&1.2.3.4.5&ISO^MR"
get(raw, "OBX[2]-5")     -> "0.9"
get(raw, "MSH-9.2")      -> "R01"
get(raw, "MSH-2")        -> "^~\\&"
get(raw, "PID-5.1")      -> "JOHNSON&JOHNSON"
get(raw, "OBX[3]-5")     -> ""

(The strings are Python literals: "^~\\&" is the four characters ^~\&.)

Example 2:

raw = "MSH#$*!%#EPIC#HOSP#LAB#HOSP#20260105083000##ADT$A01$ADT_A01#MSG00001#P#2.5\rPID#1##12345$$$HOSP$MR##DOE$JANE\r"

get(raw, "MSH-1")        -> "#"
get(raw, "MSH-9.2")      -> "A01"
get(raw, "PID-5.2")      -> "JANE"
Explanation: this sender uses # $ * ! % for field, component, repetition, escape and subcomponent.

Constraints:

  • The message starts with MSH, segments end with \r, and the five delimiter characters are all different.
  • Paths are always well-formed, segment names are three characters, and every number is at least 1.
  • MSH-1 and MSH-2 are only asked for as a whole field (no repetition, component or subcomponent).
  • The only escape sequences in the tests are the five listed above.

Follow-up: HL7 defines more escape sequences than these five, for example \.br\ for a line break in formatted text and \Xhh\ for hexadecimal data. Where in an interface should those be decoded, and where must they pass through unchanged?

Hint 1

Split from the outside in: segments, then fields, repetitions, components, subcomponents. Decode escapes last, on the final string. A decoded \F\ is a | and must never be split on.

Hint 2

Chained str.replace calls decode \E\T\ wrongly in either order. re.sub with a function as the replacement scans left to right and never rescans what it has replaced.

Reference solution 
import re

PATH = re.compile(r"([A-Z][A-Z0-9]{2})(?:\[(\d+)\])?-(\d+)(?:\[(\d+)\])?(?:\.(\d+))?(?:\.(\d+))?")


def get(raw: str, path: str) -> str:
    name, occurrence, field, repetition, component, subcomponent = PATH.fullmatch(path).groups()
    field_separator = raw[3]
    component_separator, repetition_separator, escape, subcomponent_separator = raw[4:8]

    matching = [segment for segment in raw.split("\r") if segment[:3] == name]
    fields = nth(matching, occurrence).split(field_separator)
    if name == "MSH":
        fields.insert(1, field_separator)  # MSH-1 is the separator itself
        if int(field) <= 2:
            return fields[int(field)]

    value = nth(fields[1:], field)
    value = nth(value.split(repetition_separator), repetition)
    if component:
        value = nth(value.split(component_separator), component)
    if subcomponent:
        value = nth(value.split(subcomponent_separator), subcomponent)

    decoded = {
        "F": field_separator,
        "S": component_separator,
        "T": subcomponent_separator,
        "R": repetition_separator,
        "E": escape,
    }
    sequence = re.escape(escape) + "([FSTRE])" + re.escape(escape)
    return re.sub(sequence, lambda match: decoded[match.group(1)], value)


def nth(parts: list[str], number: str | None) -> str:
    """The part at a 1-based position (1 when not given), or "" past the end."""
    index = int(number or 1) - 1
    return parts[index] if index < len(parts) else ""

mellp 06: Read the Header

Easy · parsing · msh · python-hl7

Every routing decision an interface makes starts in the MSH segment: who sent the message, who it is for, what kind of message it is, which version of the standard it follows and whether it is production traffic. Read those values once into a plain dict and the rest of your code never touches the raw text. The catch is MSH-1. The | right after MSH is not a separator in front of field 1, it is field 1, so every MSH field number is one higher than its position in raw.split("|").

def header(raw: str) -> dict[str, str]

Return a dict with exactly these ten keys:

Key Field
sending_app MSH-3
sending_facility MSH-4
receiving_app MSH-5
receiving_facility MSH-6
timestamp MSH-7, as written
type MSH-9.1
trigger MSH-9.2
control_id MSH-10
processing_id MSH-11
version MSH-12

Segments may end with \r (as on the wire), \n or \r\n (a message saved to a file by an editor). All three must work.

Example 1:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|MSG00001|P|2.5\r"
        "EVN|A01|20260105083000\r"
        "PID|1||12345^^^HOSP^MR||DOE^JANE^Q||19800214|F\r"
Output: {"sending_app": "EPIC", "sending_facility": "HOSP", "receiving_app": "LAB",
         "receiving_facility": "HOSP", "timestamp": "20260105083000", "type": "ADT",
         "trigger": "A01", "control_id": "MSG00001", "processing_id": "P", "version": "2.5"}
Explanation: raw.split("|")[9] is "MSG00001". That is MSH-10, not MSH-9.

Example 2:

Input:  the same message with "\n" after every segment instead of "\r"
Output: the same dict

Constraints:

  • The first segment is MSH and the message uses the default delimiters |^~\&.
  • MSH-3 through MSH-12 are present and non-empty. MSH-9 has at least two components.
  • MSH-3 to MSH-7 and MSH-10 to MSH-12 hold a single value with no components.
  • One message uses one kind of line ending throughout.

Follow-up: MSH-3 is an HD (hierarchic designator) with up to three components: namespace ID, universal ID and universal ID type. When a sender fills all three, what should sending_app contain, and what would you route on?

Hint 1

python-hl7 numbers MSH fields the HL7 way, so the off-by-one is handled for you:

msg = hl7.parse(raw)
msg["MSH.F10"]          # "MSG00001"
msg["MSH.F9.R1.C2"]     # "A01"

The hl7apy equivalent of the second line is parse_message(raw).msh.msh_9.msh_9_2.value.

Hint 2

python-hl7 splits segments on \r only. Given \n line endings it sees one long MSH segment, and msg["MSH.F12"] comes back as "2.5\nEVN". Normalise the line endings before parsing.

import hl7

mellp 07: Find the Patient

Easy · parsing · pid · python-hl7

Nearly every inbound message has to be matched to a patient before anything else happens, and the PID segment is where the identity lives: the medical record number in PID-3, the name in PID-5, birth date in PID-7, administrative sex in PID-8. HL7 writes dates as 19800214, while most systems downstream (a FHIR server, a JSON API, a database column) want 1980-02-14. Pull out the five values in the shape the next system expects.

def patient(raw: str) -> dict

Return a dict with exactly these keys:

  • mrn: PID-3.1 of the first repetition of PID-3
  • family: PID-5.1
  • given: PID-5.2
  • dob: "YYYY-MM-DD" built from the first 8 digits of PID-7, or None when PID-7 is empty. PID-7 may carry a time after the date (198002141230); ignore it.
  • sex: PID-8, or None when it is empty

Raise ValueError when the message has no PID segment.

Example 1:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|MSG00001|P|2.5\r"
        "EVN|A01|20260105083000\r"
        "PID|1||12345^^^HOSP^MR||DOE^JANE^Q||19800214|F\r"
        "PV1|1|I|ICU^101^A\r"
Output: {"mrn": "12345", "family": "DOE", "given": "JANE", "dob": "1980-02-14", "sex": "F"}

Example 2:

Input:  "MSH|^~\\&|LAB|HOSP|EPIC|HOSP|20260105083000||ORU^R01^ORU_R01|MSG00003|P|2.5\r"
        "PID|1||12345^^^HOSP^MR~987654321^^^SSA^SS||DOE^JANE||198002141230|\r"
        "OBR|1|ORD448^EPIC|LAB7731^LAB|24323-8^Comprehensive metabolic panel^LN\r"
Output: {"mrn": "12345", "family": "DOE", "given": "JANE", "dob": "1980-02-14", "sex": None}
Explanation: PID-3 has two repetitions and the first is the MRN. PID-7 carries a time.
             PID-8 is empty. PID is the second segment here, not the third.

Example 3:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|MSG00001|P|2.5\r"

Output: raises ValueError

Constraints:

  • Segments end with \r and the message uses the default delimiters |^~\&.
  • There is at most one PID segment, and it can be anywhere after MSH.
  • PID-5, when the PID is there, has at least two components (family and given).
  • PID-7 is either empty or starts with 8 digits YYYYMMDD.

Follow-up: the MRN is not always the first repetition of PID-3. Other identifiers, such as a social security number, can come first, and PID-3.5 (identifier type code, MR for medical record number, SS for social security number) says which is which. How would you pick the right one? Problem 08 builds the tool.

mellp 11: Lab Results

Easy · parsing · oru · obx · python-hl7

A lab result arrives as an ORU^R01: an OBR for the ordered test, then one OBX per observation. OBX-2 names the value type, and it matters: NM (numeric) values get charted, trended and compared against ranges, so they have to become numbers, while ST (string) values stay text. Turn the OBX segments into a list of plain dicts.

def observations(raw: str) -> list[dict]

Return one dict per OBX segment, in message order:

  • code: OBX-3.1 (the observation identifier, here a LOINC code)
  • name: OBX-3.2
  • value: float(OBX-5) when OBX-2 is NM, otherwise OBX-5 as a string
  • units: OBX-6.1, or None when empty
  • flag: OBX-8 (abnormal flag), or None when empty
  • status: OBX-11 (result status)

A message with no OBX gives [].

Example 1:

Input:  "MSH|^~\\&|LAB|HOSP|EPIC|HOSP|20260105083000||ORU^R01^ORU_R01|MSG00003|P|2.5\r"

        "OBR|1|ORD448^EPIC|LAB7731^LAB|24323-8^Comprehensive metabolic panel^LN\r"
        "OBX|1|NM|2345-7^Glucose^LN||182|mg/dL|70-99|H|||F\r"
        "OBX|2|ST|5778-6^Color of Urine^LN||YELLOW||||||F\r"
Output: [{"code": "2345-7", "name": "Glucose", "value": 182.0, "units": "mg/dL",

import hl7


def observations(raw: str) -> list[dict]:
    message = hl7.parse(raw)
    # message.segments("OBX") raises KeyError when there are none, so count them instead.
    count = sum(1 for segment in message if str(segment[0]) == "OBX")
    return [observation(message, f"OBX{number}") for number in range(1, count + 1)]


def observation(message: hl7.Message, obx: str) -> dict:
    """One OBX, addressed as "OBX1", "OBX2", ... in python-hl7 accessor keys."""

START, END = b"\x0b", b"\x1c\x0d"


class MllpReader:
    def __init__(self):
        self.buffer = bytearray()

    def feed(self, chunk: bytes) -> list[str]:
        self.buffer += chunk
        messages = []
        while True:
            start = self.buffer.find(START)
            if start == -1:
                self.buffer.clear()  # no frame started: everything is noise
                break
            del self.buffer[:start]
            end = self.buffer.find(END)
            if end == -1:
                break  # incomplete frame, wait for more bytes
            messages.append(self.buffer[1:end].decode("ascii"))
            del self.buffer[:end + len(END)]
        return messages

mellp 01: Wrap It

Easy · framing · stdlib

TCP delivers a stream of bytes with no message boundaries. MLLP (Minimal Lower Layer Protocol) adds them by putting every HL7 message inside a block:

<SB>  payload  <EB><CR>
0x0B   ...     0x1C 0x0D

SB is the start-of-block byte (ASCII vertical tab), EB the end-of-block byte (ASCII file separator), and a carriage return closes the block. The payload is the HL7 message itself, segments and their \r terminators included.

Implement both directions:

def frame(payload: bytes) -> bytes
def unframe(block: bytes) -> bytes
  • frame wraps payload in one block.
  • unframe takes exactly one block and returns its payload.
  • A payload may not contain 0x0B or 0x1C. Both functions raise ValueError for one that does.
  • unframe raises ValueError for anything that is not exactly one block: missing SB, missing EB or CR, or bytes before or after the block.

Example 1:

Input:  frame(b"MSH|^~\\&|EPIC\r")
Output: b"\x0bMSH|^~\\&|EPIC\r\x1c\r"

Example 2:

Input:  unframe(b"\x0bMSH|^~\\&|EPIC\r\x1c\r")
Output: b"MSH|^~\\&|EPIC\r"
Explanation: the \r before \x1c is the last segment's terminator and belongs to the payload.

Example 3:

Input:  unframe(b"\x0bMSH|^~\\&|EPIC\r\x1c\r\n")
Output: ValueError
Explanation: a trailing newline is not part of the block.

Constraints:

  • 0 <= len(payload) <= 10**6
  • An empty payload is legal: frame(b"") == b"\x0b\x1c\r".
  • Work with bytes. Do not decode.

Follow-up: some senders really do append \n after the block, and some payloads arrive without the final segment terminator. Which of the two would you tolerate in a receiver, and where?

Hint

bytes.startswith, bytes.endswith and slicing are enough. Remember the end marker is two bytes.

EB = b"\x1c\x0d"

    if SB in payload or b"\x1c" in payload:

mellp 04: Noisy Line

Medium · framing · resync · stdlib

Real peers are not as tidy as problem 03 assumed. Some append \n after every block. Some die halfway through a message and start a new one. A misconfigured one sends an endless block that would eat all your memory. A receiver that survives a production feed needs rules for all three.

class Deframer:
    discarded: int

    def __init__(self, max_size: int = 1_048_576) -> None
    def feed(self, chunk: bytes) -> list[bytes]

feed returns the payloads of the blocks completed by this chunk, as in problem 03, with these additions:

  1. Noise outside a block is dropped. Bytes before the first SB, and bytes between an end marker and the next SB, are thrown away.
  2. A new SB restarts the block. If SB arrives while a block is open, the open block was abandoned by its sender: throw it away and begin a new block at this SB.
  3. Oversized blocks are dropped. A block whose payload is longer than max_size bytes is never returned. As soon as an open block is known to exceed the limit, stop buffering it and treat what follows as noise until the next SB.
  4. discarded counts every dropped byte, marker bytes of dropped blocks included.

Example 1:

d = Deframer()
d.feed(b"\x0bA\x1c\r\r\n\x0bB\x1c\r")   -> [b"A", b"B"]
d.discarded                             -> 2
Explanation: the sender puts CR LF after each block.

Example 2:

d = Deframer()
d.feed(b"\x0bMSH|half a mess")          -> []
d.feed(b"\x0bMSH|whole\r\x1c\r")        -> [b"MSH|whole\r"]
d.discarded                             -> 16
Explanation: the first block (SB plus 15 payload bytes) was abandoned when the second SB arrived.

Example 3:

d = Deframer(max_size=4)
d.feed(b"\x0bABCDE\x1c\r\x0bOK\x1c\r")  -> [b"OK"]
d.discarded                             -> 8
Explanation: a 5-byte payload exceeds max_size=4. All 8 bytes of that block are dropped.

Constraints:

  • Chunks are cut anywhere, as in problem 03.
  • Payloads of well-formed blocks never contain 0x0B or 0x1C.
  • A payload of exactly max_size bytes is accepted.
  • Memory stays bounded: never hold more than about max_size bytes plus one chunk, no matter how long an unterminated block runs.
  • Accounting is exact. At any moment: bytes fed = bytes of returned blocks (payload + 3 each) + discarded + bytes still buffered.

class Deframer:
    def __init__(self, max_size: int = 1_048_576) -> None:
        self.max_size = max_size
        self.discarded = 0
        self._buffer = bytearray()  # empty, or starts with the SB of the open block

    def feed(self, chunk: bytes) -> list[bytes]:
        self._buffer += chunk
        payloads = []
        while self._buffer:
            if self._buffer[0] != SB[0]:  # outside a block: drop noise up to the next SB
                self._drop(self._buffer.find(SB))
                continue
            end = self._buffer.find(EB, 1)
            restart = self._buffer.find(SB, 1)
            if restart != -1 and (end == -1 or restart < end):  # abandoned by its sender
                self._drop(restart)
            elif end == -1:
                # Still open. One extra byte of slack: a trailing 0x1C may be half an end marker.
                if len(self._buffer) - 1 > self.max_size + 1:
                    self._drop(-1)
                break
            elif end - 1 > self.max_size:
                self._drop(end + len(EB))
            else:
                payloads.append(bytes(self._buffer[1:end]))
                del self._buffer[: end + len(EB)]
        return payloads

    def _drop(self, count: int) -> None:
        """Discards the first `count` buffered bytes; -1 discards them all."""
        if count == -1:
            count = len(self._buffer)
        self.discarded += count
        del self._buffer[:count]

mellp 16: Send and Wait

Easy · sockets · client · timeout · stdlib

Now the other side of the call. Your system has a message for the lab and must know whether the lab accepted it. Sending is the easy part. The work is in everything that can happen while you wait: the lab answers, the lab says nothing, the lab hangs up, or the lab hangs up halfway through its answer.

def send(host: str, port: int, payload: bytes, timeout: float = 5.0) -> bytes

Connect, send payload as one block, wait for one reply block, and return its payload.

  1. If the server sends nothing for timeout seconds while you wait, raise TimeoutError.
  2. If the server closes the connection before a complete reply block arrived (no reply at all, or only part of one), raise ConnectionError.
  3. A refused connection raises ConnectionRefusedError, which is already a subclass of ConnectionError. Let it propagate.

An AE or AR acknowledgment is still a reply: return it. Deciding what to do with it is problem 18.

mellp 17: Keep the Line Open

Medium · sockets · client · long-lived · stdlib

Problem 16 opened a connection per message. Real feeds do not: an ADT feed opens one connection and keeps it for hours or days, sending message after message and waiting for each ACK before the next. That saves a handshake per message, but it adds state. Bytes that belong to the next reply can arrive with this one, and once a reply goes missing, the conversation can quietly slip out of step.

class Session:
    def __init__(self, host: str, port: int, timeout: float = 5.0) -> None   # connects
    def send(self, payload: bytes) -> bytes
    def close(self) -> None
    def __enter__(self) -> "Session"
    def __exit__(self, *exc) -> None

send sends one block and returns the payload of the reply block, like problem 16, but over the session's single connection.

  1. One connection. The constructor connects. Every send uses that connection; nothing ever reconnects.
  2. Replies arrive in pieces. If bytes beyond the end of a reply arrive, they are the start of the next reply: keep them for the next send.
  3. The reply must match. If the reply's MSA-2 differs from the MSH-10 of the message just sent, raise ConnectionError.
  4. A failure breaks the session. TimeoutError when the server sends nothing for timeout seconds, ConnectionError when it closes before a complete reply (or any other socket error): close the socket and re-raise. Every later send raises ConnectionError without sending anything.
  5. Closing. close() may be called any number of times. send after close raises ConnectionError. Leaving a with block closes the session.

Why rule 4 is so strict: suppose the ACK for message 2 is late. You time out and send message 3. The late ACK for message 2 now arrives and is read as the answer to message 3. From then on every ACK is off by one, and a rejection of message 7 is reported against message 8. Rule 3 catches one such mismatch, and closing the connection is the only safe recovery: a new connection starts with no old replies in flight.

Example 1:

s.send(adt_1)      -> b"MSH|...\rMSA|AA|MSG00001\r"
s.send(adt_2)      -> b"MSH|...\rMSA|AA|MSG00002\r"
Explanation: both messages travel over the same connection.

Example 2:

s.send(adt_1)      -> TimeoutError
s.send(adt_2)      -> ConnectionError              adt_2 is never sent

Example 3:

s = Session("127.0.0.1", 2575)                    the server answers message 1 with "MSA|AA|WRONG"
s.send(adt_1)      -> ConnectionError
s.send(adt_2)      -> ConnectionError

Constraints:

  • Over the whole connection the server sends at most one reply block per message, in order, and no bytes outside blocks. Where one read ends is up to the network.
  • Every message has a non-empty MSH-10. Every reply has an MSA segment.
  • Payloads never contain 0x0B or 0x1C. Segments end with \r.
  • A refused connection makes the constructor raise ConnectionRefusedError (a ConnectionError).

Follow-up: a broken session loses the connection, but the caller still has a message that may or may not have been processed. Should the caller reconnect and resend? Problem 18 says how often, problem 19 makes resending safe for the receiver.

import socket

SB = b"\x0b"
EB = b"\x1c\x0d"


def fields(message: bytes, name: bytes) -> list[bytes]:
    """The `|`-separated parts of the first segment called `name`. For MSH, MSH-n is part n - 1."""
    for segment in message.split(b"\r"):
        if segment.startswith(name + b"|"):
            return segment.split(b"|")
    return []


class Session:
    def __init__(self, host: str, port: int, timeout: float = 5.0) -> None:
        self._sock: socket.socket | None = socket.create_connection((host, port), timeout=timeout)
        self._buffer = b""

    def send(self, payload: bytes) -> bytes:
        if self._sock is None:
            raise ConnectionError("the session is closed")
        try:
            self._sock.sendall(SB + payload + EB)
            reply = self._read_block()
            if fields(reply, b"MSA")[2] != fields(payload, b"MSH")[9]:
                raise ConnectionError("the reply acknowledges a different message")
        except OSError:  # TimeoutError and ConnectionError included: the stream is out of step
            self.close()
            raise
        return reply

    def _read_block(self) -> bytes:
        while (end := self._buffer.find(EB)) == -1:
            chunk = self._sock.recv(65536)
            if not chunk:
                raise ConnectionError("the server closed the connection")
            self._buffer += chunk
        block = self._buffer[self._buffer.find(SB) + 1 : end]
        self._buffer = self._buffer[end + len(EB) :]
        return block

    def close(self) -> None:
        if self._sock is not None:
            self._sock.close()
            self._sock = None

    def __enter__(self) -> "Session":
        return self

    def __exit__(self, *exc) -> None:
        self.close()

mellp 20: Many Callers

Medium · sockets · server · threads · stdlib

A real receiver does not answer one call and hang up. The registration system, the lab system and the pharmacy system each open a connection in the morning and keep it open all day, sending a message whenever something happens. One of them may go quiet for an hour, and one may die halfway through a message. None of that may hold up the others.

def serve(
    listener: socket.socket,
    handler: Callable[[bytes], bytes],
    stop: threading.Event,
) -> None

listener is already bound and listening. serve blocks until stop is set.

  1. Every connection is long-lived: the client sends any number of messages, and gets one reply block per message, handler(payload), in the order it sent them, until it closes the connection.
  2. Connections are served concurrently. A client that is idle, slow, or stuck halfway through a message delays nobody else.
  3. A client that disconnects, even in the middle of a message or with a TCP reset, does not disturb the server or the other clients. A half-received message is never passed to handler.
  4. Within 1 s of stop.set(), serve returns, and the connections it accepted are closed.

Example 1:

client A connects, sends MSG00001, MSG00002, MSG00003 in one write
client A receives the replies for MSG00001, MSG00002, MSG00003, in that order
client A stays connected and sends MSG00004 ten minutes later: it gets its reply

Example 2:

client A connects and sends nothing
client B connects, sends half of MSG00001 and stalls
client C connects, sends MSG00002          -> gets its reply at once
client B sends the rest of MSG00001        -> gets its reply

Example 3:

handler sleeps 0.02 s per message
20 clients each send 20 messages, one at a time, waiting for each reply
a server that serves one client at a time needs 20 * 20 * 0.02 = 8 s
yours finishes in well under 4 s

Constraints:

  • handler never raises and returns the reply payload, unframed.
  • Clients send well-formed blocks with nothing between them, though a block may arrive in pieces and several blocks may arrive in one read.
  • Payloads never contain 0x0B or 0x1C.
  • Tests run up to 20 clients at once. serve does not close listener; the caller does.

Follow-up: one thread per connection is fine for twenty interfaces. What breaks at ten thousand idle connections, and what would you change? Problem 21 is one answer.

Hint 1

One thread runs the accept loop; each accepted connection gets its own thread (threading.Thread(target=..., daemon=True)) running a receive loop like the one in problem 15, which keeps going instead of returning after one reply. recv() returns b"" on a clean close and raises ConnectionResetError (an OSError) on a reset.

Hint 2

accept() blocks forever and never looks at stop. listener.settimeout(0.1) makes it raise TimeoutError every 0.1 s so the loop can check. Accepted sockets do not inherit that timeout. To close connections whose threads are blocked in recv(), keep them in a set guarded by a threading.Lock and call conn.shutdown(socket.SHUT_RDWR) on each: the blocked recv() returns b"" and the thread finishes on its own.

import socket
import threading
from collections.abc import Callable

SB = b"\x0b"
EB = b"\x1c\x0d"


def serve(
    listener: socket.socket,
    handler: Callable[[bytes], bytes],
    stop: threading.Event,
) -> None:
    connections: set[socket.socket] = set()
    lock = threading.Lock()  # guards `connections`

    def converse(conn: socket.socket) -> None:
        """Answers one client's messages in order until it hangs up."""
        buffer = b""
        try:
            while chunk := conn.recv(65536):
                buffer += chunk
                while (end := buffer.find(EB)) != -1:
                    payload = buffer[buffer.find(SB) + 1 : end]
                    buffer = buffer[end + len(EB) :]
                    conn.sendall(SB + handler(payload) + EB)
        except OSError:
            pass  # reset by the peer, or shut down by serve()
        finally:
            with lock:
                connections.discard(conn)
            conn.close()

    listener.settimeout(0.1)  # accept() wakes up regularly to look at `stop`
    while not stop.is_set():
        try:
            conn, _ = listener.accept()
        except TimeoutError:
            continue
        with lock:
            connections.add(conn)
        threading.Thread(target=converse, args=(conn,), daemon=True).start()
    with lock:
        for conn in connections:
            try:
                conn.shutdown(socket.SHUT_RDWR)  # wakes the worker blocked in recv()
            except OSError:
                pass  # the peer is already gone

import hl7
import hl7.mllp


async def start(
    handler: Callable[[hl7.Message], Awaitable[hl7.Message]],
    host: str = "127.0.0.1",
    port: int = 0,

    async def converse(reader: hl7.mllp.HL7StreamReader, writer: hl7.mllp.HL7StreamWriter) -> None:

mellp 10: AA, AE or AR

Medium · ack · validation · python-hl7

In original-mode acknowledgment, MSA-1 carries one of three codes from HL7 Table 0008: AA application accept, AE application error, AR application reject. This problem uses the following convention to choose between the last two. AR means this interface will never accept the message as addressed: a message type it does not handle, a version it does not speak, or a processing ID other than P (production; Table 0103 also has T training and D debugging). Resending it unchanged is pointless. AE means the message is the right kind but its content is wrong, so someone has to fix the data.

SUPPORTED_TYPES = {"ADT^A01", "ADT^A08", "ORU^R01", "ORM^O01"}
SUPPORTED_VERSIONS = {"2.3", "2.3.1", "2.4", "2.5", "2.5.1"}

def respond(raw: bytes) -> bytes

  1. MSH-12 not in SUPPORTED_VERSIONS: AR, text unsupported version: <MSH-12>

  5. PID-3.1 empty: AE, text PID-3 is required
  6. PID-5.1 empty: AE, text PID-5 is required
  7. otherwise AA with no text

The ACK is the one from problem 09: MSH with the parties swapped, MSH-9 ACK^<trigger>, MSH-11 and MSH-12 copied, MSA-1 the code, MSA-2 the original MSH-10, MSA-3 the text. Encode it as UTF-8.

mellp 18: Try, Try Again

Medium · retries · backoff · ack codes · stdlib

A lab result that never reaches the chart is a patient-safety problem, so senders retry. Retrying blindly is its own problem: hammering a receiver that is restarting keeps it down, and resending a message the receiver has refused fills its error queue with copies. A sender needs a policy for every outcome of a send.

class Rejected(Exception): ...

class DeliveryFailed(Exception):
    def __init__(self, attempts: int, reason: str) -> None: ...   # sets .attempts and .reason

def deliver(
    payload: bytes,
    send: Callable[[bytes], bytes],
    *,
    retries: int = 3,
    backoff: float = 0.5,
    sleep: Callable[[float], None] = time.sleep,
) -> int

send delivers one payload and returns the reply payload: problem 16 with host and port filled in. deliver returns the number of attempts it took.

  1. Success is a reply with MSA-1 AA and MSA-2 equal to the payload's MSH-10.
  2. Retry on TimeoutError, ConnectionError (refused, reset, or closed early), an AE reply, and a reply whose MSA-2 is not this message's MSH-10. Such a reply is a stale ACK for some other message, whatever its code.
  3. Rejection: an AR reply for this message raises Rejected at once, with MSA-3 as the exception message. A rejected message is never sent again.
  4. Attempts: at most 1 + retries. Before retry k (k = 1, 2, ...) call sleep(backoff * 2 ** (k - 1)). Never sleep after the last attempt.
  5. Giving up: when the attempts run out, raise DeliveryFailed(attempts, reason), where reason is a short non-empty description of the last failure.
  6. Same payload every time. Every attempt sends the identical bytes, same MSH-10, so the receiver can recognise a duplicate.
  7. Anything else propagates. Any other exception from send is not caught, not wrapped, and not retried.

Retrying AE is this problem's policy, not a rule of HL7. In real life the receiving system's interface specification decides which codes are worth a retry.

Example 1:

send outcomes:   TimeoutError, reply MSA|AE|MSG00001, reply MSA|AA|MSG00001
deliver(adt, send)          -> 3
sleep calls:     0.5, 1.0

Example 2:

send outcomes:   reply MSA|AR|MSG00001|unknown patient
deliver(adt, send)          -> raises Rejected("unknown patient"), after one attempt and no sleep

Example 3:

send outcomes:   TimeoutError, TimeoutError
deliver(adt, send, retries=1, backoff=2.0)  -> raises DeliveryFailed, .attempts == 2
sleep calls:     2.0

Constraints:

  • retries >= 0, backoff > 0.
  • payload has a non-empty MSH-10. Every reply has an MSA segment whose MSA-1 is AA, AE or AR.
  • Segments end with \r.
  • Tests pass a recording sleep that returns at once, plus one test against a real server that closes, stays silent, answers AE, and finally answers AA.

Follow-up: 2 ** k grows without bound and every sender that failed at the same moment retries at the same moment. How would you cap the delay, and why do production retry loops add random jitter?

Hint

A for attempt in range(...) loop with a try / except (TimeoutError, ConnectionError) around send, and continue for everything worth another try. Check MSA-2 before looking at the code: a stale AR belongs to another message.

import time
from collections.abc import Callable


class Rejected(Exception):
    """The receiver answered AR: resending the same message cannot help."""


class DeliveryFailed(Exception):
    def __init__(self, attempts: int, reason: str) -> None:
        super().__init__(f"gave up after {attempts} attempts: {reason}")
        self.attempts = attempts
        self.reason = reason


def field(message: bytes, segment: bytes, number: int) -> str:
    """Field `number` of the first `segment` segment, or "" if there is none."""
    for line in message.split(b"\r"):
        values = line.split(b"|")
        if values[0] == segment:
            if segment == b"MSH":
                values.insert(1, b"|")  # MSH-1 is the field separator itself
            return values[number].decode() if number < len(values) else ""
    return ""


def deliver(
    payload: bytes,
    send: Callable[[bytes], bytes],
    *,
    retries: int = 3,
    backoff: float = 0.5,
    sleep: Callable[[float], None] = time.sleep,
) -> int:
    control_id = field(payload, b"MSH", 10)
    attempts = 1 + retries
    for attempt in range(1, attempts + 1):
        if attempt > 1:
            sleep(backoff * 2 ** (attempt - 2))
        try:
            reply = send(payload)
        except (TimeoutError, ConnectionError) as error:
            reason = f"{type(error).__name__}: {error}"
            continue
        code = field(reply, b"MSA", 1)
        if field(reply, b"MSA", 2) != control_id:
            reason = f"stale {code} for {field(reply, b'MSA', 2)!r}"
        elif code == "AR":
            raise Rejected(field(reply, b"MSA", 3))
        elif code == "AA":
            return attempt
        else:
            reason = code
    raise DeliveryFailed(attempts, reason)

mellp 19: Seen It Before

Easy · idempotency · duplicates · stdlib

The sender in problem 18 resends when an ACK goes missing. But a missing ACK does not mean a missing message: often the receiver processed the admit, and only the ACK was lost on the way back. Without protection, the resend admits the patient a second time. The receiver has to recognise the resend by its control ID (MSH-10) and answer it without doing the work again.

class Deduplicator:
    def __init__(self, process: Callable[[bytes], bytes], capacity: int = 1000) -> None
    def __call__(self, payload: bytes) -> bytes

A Deduplicator wraps a handler. process does the real work and returns the reply payload.

  1. The first time a control ID is seen, call process(payload) and return its reply.
  2. If that reply's MSA-1 is AA, remember the reply under the control ID.
  3. When a remembered control ID comes again, return the remembered reply without calling process.
  4. A reply that is not AA is not remembered, and neither is a call where process raises (let the exception propagate). The resend must be processed for real.
  5. Remember at most capacity control IDs. When a new one would exceed that, forget the one remembered longest ago.

dedup(admit_MSG00001)       -> b"MSH|...\rMSA|AA|MSG00001\r"      process not called

Example 2:

dedup(admit_MSG00001)       -> b"MSH|...\rMSA|AE|MSG00001\r"      process called
dedup(admit_MSG00001)       -> b"MSH|...\rMSA|AA|MSG00001\r"      process called again
Explanation: the first attempt failed, so the resend is real work.

Example 3:

dedup(m1); dedup(m2); dedup(m3)      process called 3 times, m1 is forgotten
dedup(m1)                            process called again

Constraints:

  • MSH is the first segment of every payload and its MSH-10 is non-empty. Segments end with \r.
  • Every reply from process is an acknowledgment whose second segment is MSA.
  • Only the control ID decides: a different message with a control ID already remembered gets the remembered reply.
  • capacity >= 1. Calls come from one thread.

Follow-up: the memory lives in the process, so a restart forgets everything and two receivers behind a load balancer do not share it. Where would you keep it instead, and for how long?

class Deduplicator:
    def __init__(self, process: Callable[[bytes], bytes], capacity: int = 1000) -> None:
        self.process = process
        self.capacity = capacity
        self._replies: OrderedDict[bytes, bytes] = OrderedDict()  # control ID -> AA reply

mellp 23: Exactly Once

Hard · retries · duplicates · chaos · stdlib

When an ACK is lost, the sender cannot know whether the receiver processed the message. It has two choices: give up and risk losing a lab result, or resend and risk admitting the patient twice. The network cannot promise "exactly once", but the two ends together can: the sender resends until it gets an AA (at least once), and the receiver recognises a resend by its control ID and does not process it again (at most once). This problem puts problems 17, 18, 19 and 20 together and runs them through a network that misbehaves on purpose.

ACK = "MSH|^~\\&|||||||ACK|ACK{control_id}|P|2.5\rMSA|{code}|{control_id}\r"

class Sender:
    def __init__(self, host: str, port: int, timeout: float = 0.5, retries: int = 10) -> None
    def send(self, payload: bytes) -> bytes      # the AA reply payload
    def close(self) -> None

def serve(listener: socket.socket, process: Callable[[bytes], None], stop: threading.Event) -> None

Sender

  1. Keeps one connection open across sends. It connects when it has no connection, including on the first send.
  2. Success is a reply with MSA-1 AA and MSA-2 equal to the payload's MSH-10; send returns that reply payload. On a timeout (no reply within timeout seconds), a lost connection, or any other reply: close the connection, connect again, and resend the identical payload. A connection that failed is never reused.
  3. After 1 + retries attempts without success, raise DeliveryFailed.

Receiver (serve blocks until stop is set and returns within 1 s of it, closing its connections)

  1. Serves connections concurrently; each connection is long-lived, one reply per message, in order.
  2. For a control ID (MSH-10) not yet processed: call process(payload), then reply AA. If process raises, reply AE and do not count the message as processed: the resend must be processed for real.
  3. For a control ID already processed: reply AA again without calling process.
  4. process never runs twice at the same time for the same control ID. A message whose control ID is being processed on another connection waits for that to finish, then rules 5 and 6 apply.

Replies are ACK.format(control_id=..., code="AA") (or "AE"), framed. Rule 2 matters for the reason problem 17 gave: after a timeout, the late ACK can still arrive on the old connection, and a sender that kept reading there would take it for the reply to whatever it sent next.

Example 1: the ACK is lost.

receiver   processes MSG00001, replies AA

receiver   process raises (database unavailable): replies AE

receiver   MSG00002 not processed yet: process succeeds, replies AA

receiver   processes MSG00003, replies AA; the network holds it for 0.4 s
sender     no reply within 0.15 s: TimeoutError, closes connection 1
sender  -> MSG00003 on connection 2, gets AA (a duplicate, not processed again)
           the late AA arrives on connection 1, which nobody reads any more

Constraints:

  • Every logical message has its own non-empty MSH-10; a resend carries the same one.
  • send is never called from two threads at once.
  • Payloads never contain 0x0B or 0x1C; blocks may arrive in pieces, with nothing between them.
  • process may raise any Exception. The receiver's memory of processed IDs may grow without limit here.
  • The main test sends 300 messages through harness.chaos.ChaosProxy, which for about 35% of requests (fixed seed) drops the ACK and closes, cuts the request in half and closes, relays one byte per write, or delivers the ACK 0.4 s late. from collections.abc import Callable

SB = b"\x0b"

class DeliveryFailed(Exception):
    pass


def field(payload: bytes, segment: bytes, index: int) -> bytes:
    """Field `index` of the first `segment` (for MSH the index is one less than MSH-n)."""
    for line in payload.split(b"\r"):
        fields = line.split(b"|")
        if fields[0] == segment:
            return fields[index] if index < len(fields) else b""
    return b""


class Sender:
    def __init__(self, host: str, port: int, timeout: float = 0.5, retries: int = 10) -> None:
        self.address = (host, port)
        self.timeout = timeout
        self.retries = retries
        self._sock: socket.socket | None = None
        self._buffer = b""

    def send(self, payload: bytes) -> bytes:
        control_id = field(payload, b"MSH", 9)
        for _ in range(1 + self.retries):
            try:
                reply = self._exchange(payload)
            except OSError:  # TimeoutError, ConnectionError, refused
                self.close()
                continue
            if field(reply, b"MSA", 1) == b"AA" and field(reply, b"MSA", 2) == control_id:
                return reply
            self.close()  # an AE, or a stale reply: this connection is out of step
        raise DeliveryFailed(f"{control_id.decode()}: no AA after {1 + self.retries} attempts")

    def close(self) -> None:
        if self._sock is not None:
            self._sock.close()
        self._sock = None

    def _exchange(self, payload: bytes) -> bytes:
        if self._sock is None:
            self._sock = socket.create_connection(self.address, timeout=self.timeout)
            self._buffer = b""
        self._sock.sendall(SB + payload + EB)
        while EB not in self._buffer:
            chunk = self._sock.recv(65536)
            if not chunk:
                raise ConnectionError("receiver closed the connection")
            self._buffer += chunk
        end = self._buffer.find(EB)
        reply = self._buffer[self._buffer.find(SB) + 1 : end]
        self._buffer = self._buffer[end + len(EB) :]
        return reply


def serve(
    listener: socket.socket,
    process: Callable[[bytes], None],
    stop: threading.Event,
) -> None:
    receiver = Receiver(process)
    listener.settimeout(0.1)  # accept() wakes up regularly to look at `stop`
    while not stop.is_set():
        try:
            conn, _ = listener.accept()
        except TimeoutError:
            continue
        with receiver.lock:
            receiver.connections.add(conn)
        threading.Thread(target=receiver.converse, args=(conn,), daemon=True).start()
    with receiver.lock:
        for conn in receiver.connections:
            try:
                conn.shutdown(socket.SHUT_RDWR)  # wakes the worker blocked in recv()
            except OSError:
                pass  # the sender is already gone


class Receiver:
    def __init__(self, process: Callable[[bytes], None]) -> None:
        self.process = process
        self.processed: set[bytes] = set()
        self.processing = threading.Lock()  # one at a time: no ID is processed twice at once
        self.connections: set[socket.socket] = set()
        self.lock = threading.Lock()  # guards `connections`

    def converse(self, conn: socket.socket) -> None:
        buffer = b""
        try:
            while chunk := conn.recv(65536):
                buffer += chunk
                while (end := buffer.find(EB)) != -1:
                    payload = buffer[buffer.find(SB) + 1 : end]
                    buffer = buffer[end + len(EB) :]
                    conn.sendall(SB + self.handle(payload) + EB)
        except OSError:
            pass  # the sender went away; it will resend on a new connection
        finally:
            with self.lock:
                self.connections.discard(conn)
            conn.close()

    def handle(self, payload: bytes) -> bytes:
        control_id = field(payload, b"MSH", 9)
        with self.processing:
            if control_id not in self.processed:
                try:
                    self.process(payload)
                except Exception:
                    return ack(control_id, "AE")
                self.processed.add(control_id)
        return ack(control_id, "AA")


def ack(control_id: bytes, code: str) -> bytes:
    return ACK.format(control_id=control_id.decode(), code=code).encode()

mellp 24: Unbreakable Listener

Hard · sockets · server · limits · graceful shutdown · stdlib

Problem 20's server works as long as every peer behaves. A production listener faces a peer that connects and never speaks, a misconfigured system that streams a block with no end, a handler that throws on a message it cannot store, a port scanner that opens hundreds of connections, and a deployment that restarts the service while a message is half processed. Each one, unhandled, either takes the listener down or quietly loses a message. Harden the server against all of them.

def serve(
    listener: socket.socket,
    handler: Callable[[bytes], bytes],
    stop: threading.Event,
    *,
    idle_timeout: float = 30.0,
    max_size: int = 1_048_576,
    max_connections: int = 100,

serve blocks until stop is set, as in problem 20.

  1. Concurrent, long-lived connections. Any number of messages per connection, one reply per message, in order. A slow client delays nobody else.
  2. Idle timeout. A connection on which no bytes arrive for idle_timeout seconds is closed. This also catches a peer stuck halfway through a message. Time the server spends in handler does not count against the peer.
  3. Size limit. When a block's payload is longer than max_size bytes, close the connection without a reply, and do not wait for the end of the block to find out: the server never buffers much more than max_size bytes per connection. A payload of exactly max_size bytes is fine.
  4. Handler errors. If handler raises, reply with ERROR_ACK (an AE whose MSA-2 is the message's MSH-10, with any unique own_id) and keep serving the connection.
  5. Graceful stop. After stop.set(), no new connection is served. A message whose handler is already running still gets its reply. Then every connection is closed and serve returns.
  6. Noise between blocks is ignored, as in problem 04 rule 1: bytes before a block's 0x0B are dropped.
  7. Connection limit. While max_connections connections are open, a new connection is closed as soon as it is accepted.

Example 1:

idle_timeout=0.3
client connects and sends nothing          -> closed after about 0.3 s
client sends a message every 0.15 s         -> stays open, every message answered

Example 2:

max_size=1000
client sends a block with a 1000-byte payload    -> AA
client sends a block with a 1001-byte payload    -> connection closed, no reply, handler not called
client sends 0x0B and then bytes without end     -> closed once the payload passes 1001 bytes

Example 3:

client A's message is in the handler, which takes a while
stop.set()
client B connects and sends a message      -> no reply
the handler returns                        -> client A gets its reply, then A is closed
serve returns

Constraints:

  • Tests use idle_timeout=0.3, max_size=1000, max_connections=3 unless they say otherwise.
  • A complete block's payload never contains 0x0B or 0x1C. Noise between blocks may contain anything except 0x0B.
  • Every message has an MSH segment with an MSH-10.
  • serve does not close listener; the caller does, after serve returns.

Follow-up: rule 5 waits for the handler however long it takes. Most service managers send SIGTERM, wait a fixed time, then kill the process. What would you do with a handler that is still running when that time is almost up, and what does the sender see in each case?

Hint 1

One flag cannot interrupt a thread blocked in recv(), so do not block forever: conn.settimeout(0.05) makes recv() raise TimeoutError every 0.05 s. On each wake-up check stop and how long ago the last byte arrived (time.monotonic()). The same loop then gives you rules 2 and 5: a thread that is inside handler is not in recv(), so it finishes the reply before it next looks at stop. serve can join() every connection thread before it returns.

Hint 2

For the size limit, check the open block after every read, not only when its end arrives. Allow one byte of slack, as in problem 04 hint 2: a block whose payload is exactly max_size bytes can sit in the buffer with its 0x1C but not yet its 0x0D.

class Server:
    def __init__(self, handler, stop: threading.Event, idle_timeout: float, max_size: int):
        self.handler = handler
        self.stop = stop
        self.idle_timeout = idle_timeout
        self.max_size = max_size
        self.workers: set[threading.Thread] = set()
        self.lock = threading.Lock()  # guards `workers`

    def admit(self, conn: socket.socket, max_connections: int) -> None:
        with self.lock:
            if len(self.workers) >= max_connections:
                conn.close()
                return
            worker = threading.Thread(target=self.serve_connection, args=(conn,))
            self.workers.add(worker)
            worker.start()

    def finish(self) -> None:
        """Waits for every connection to deliver the reply in flight and close."""
        with self.lock:
            running = list(self.workers)
        for worker in running:
            worker.join()

    def serve_connection(self, conn: socket.socket) -> None:
        try:
            with conn:
                self.converse(conn)
        except (OSError, TooLarge):
            pass  # the peer went away, or broke the size limit: either way, close
        finally:
            with self.lock:
                self.workers.discard(threading.current_thread())

    def converse(self, conn: socket.socket) -> None:
        conn.settimeout(POLL)
        buffer = b""
        last_heard = time.monotonic()
        while not self.stop.is_set():
            if time.monotonic() - last_heard > self.idle_timeout:
                return
            try:
                chunk = conn.recv(65536)
            except TimeoutError:
                continue
            if not chunk:
                return
            buffer += chunk
            while (block := self.take_block(buffer)) is not None:
                payload, buffer = block
                conn.sendall(SB + self.reply(payload) + EB)
            buffer = self.trim(buffer)
            last_heard = time.monotonic()  # time spent in the handler is not the peer's

    def take_block(self, buffer: bytes) -> tuple[bytes, bytes] | None:
        """The first complete block's payload and what follows it, or None."""
        start = buffer.find(SB)
        end = buffer.find(EB, start + 1)
        if start == -1 or end == -1:
            return None
        if end - start - 1 > self.max_size:
            raise TooLarge
        return buffer[start + 1 : end], buffer[end + len(EB) :]

    def trim(self, buffer: bytes) -> bytes:
        """Drops noise before the open block and enforces the size limit on it."""
        start = buffer.find(SB)
        if start == -1:
            return b""
        if len(buffer) - start - 1 > self.max_size + 1:  # +1: a trailing 0x1C may begin EB
            raise TooLarge
        return buffer[start:]

    def reply(self, payload: bytes) -> bytes:
        try:
            return self.handler(payload)
        except Exception:  # an AE, not a dropped connection; the error text is not sent back
            header = payload.split(b"\r", 1)[0].split(b"|")
            control_id = header[9].decode(errors="replace") if len(header) > 9 else ""
            return ERROR_ACK.format(own_id=uuid.uuid4().hex[:20], control_id=control_id).encode()

from solutions._hl7 import field, first, part


def link_patients(messages: list[str]) -> list[list[str]]:
    parent = {}

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    for m in messages:
        pid = first(m, "PID")
        if pid is None:
            continue
        ids = []
        for rep in field(pid, 3).split("~"):
            id_, auth = part(rep, "^", 1), part(rep, "^", 4)
            if id_ and auth:
                ids.append(f"{auth}:{id_}")
        for i in ids:
            parent.setdefault(i, i)
        for i in ids[1:]:
            parent[find(i)] = find(ids[0])

    groups = {}
    for i in parent:
        groups.setdefault(find(i), []).append(i)
    return sorted(sorted(g) for g in groups.values())

mellp 32: Flatten to JSON

Easy · json · parsing · stdlib

The team next door builds dashboards and does not want to learn pipes and carets. Before anyone agrees on a real mapping, a common first step is a lossless JSON copy of each message: every non-empty field, keyed by its number, with the HL7 text left exactly as it arrived. It is enough to load into a document store and query by position.

def to_json(raw: str) -> dict[str, list[dict[str, str]]]
  1. One top-level key per segment name, in the order the names first appear in the message.
  2. Its value is a list with one dict per occurrence of that segment, in message order.
  3. Each occurrence maps the field number, as a string, to the raw text of that field. Components, repetitions and subcomponents are not split.
  4. Empty fields are left out. The segment name is not a field.
  5. MSH is numbered the HL7 way: the field separator itself is MSH-1, so "1": "|", "2": "^~\\&", and "9" is the message type.

Example 1:

Output: {"MSH": [{"1": "|", "2": "^~\\&", "3": "EPIC", "4": "HOSP", "5": "LAB", "6": "HOSP",
                  "7": "20260105083000", "9": "ADT^A01^ADT_A01", "10": "MSG00001",
                  "11": "P", "12": "2.5"}],
         "PID": [{"1": "1", "3": "12345^^^HOSP^MR", "5": "DOE^JANE"}]}

mellp 33: Patient Resource

Medium · fhir · patient · python-hl7

Sooner or later every v2 feed gets a FHIR consumer. The patient is where it starts: the same PID you have parsed since problem 07, reshaped into an R4 Patient. The mapping is mostly mechanical. What catches people is FHIR's rule that an element without a value is not sent at all, which v2 habits (an empty field is still a field) break constantly.

def to_patient(raw: str) -> dict

Return the R4 Patient as a plain dict, built from the PID segment:

FHIR Source Rule
resourceType "Patient"
identifier[] each PID-3 repetition whose ID (component 1) is not empty, in order value = PID-3.1; system = "urn:id:" + the first subcomponent of PID-3.4 when that is not empty; type = {"coding": [{"system": "http://terminology.hl7.org/CodeSystem/v2-0203", "code": PID-3.5}]} when PID-3.5 is not empty
name[0] PID-5, first repetition family = PID-5.1; given = the non-empty values of PID-5.2 and PID-5.3, in that order
gender PID-8 F -> "female", M -> "male", O -> "other", anything else (including empty) -> "unknown"
birthDate PID-7 the first 8 digits as YYYY-MM-DD

The FHIR rule: every element must have a value or children (invariant ele-1). So there is no empty string, empty list, empty dict or None anywhere in the result. An identifier without a value is skipped, a name with no parts means no name key, and so on. gender is always present.

Example 1:

Input:  "MSH|...\rPID|1||12345^^^HOSP^MR||DOE^JANE^Q||19800214|F\r"
Output: {"resourceType": "Patient",
         "identifier": [{"value": "12345", "system": "urn:id:HOSP",
                         "type": {"coding": [{"system": "http://terminology.hl7.org/CodeSystem/v2-0203",
                                              "code": "MR"}]}}],
         "name": [{"family": "DOE", "given": ["JANE", "Q"]}],
         "gender": "female",
         "birthDate": "1980-02-14"}

Example 2:

Input:  "MSH|...\rPID|1||12345\r"
Output: {"resourceType": "Patient", "identifier": [{"value": "12345"}], "gender": "unknown"}
Explanation: no authority, no type, no name, no birth date: those keys are simply not there.

Example 3:

Input:  "MSH|...\rPID|1||~^^^HOSP^MR~998877^^^STATE^SS||^JANE|||U\r"
Output: {"resourceType": "Patient",
         "identifier": [{"value": "998877", "system": "urn:id:STATE",
                         "type": {"coding": [{"system": "http://terminology.hl7.org/CodeSystem/v2-0203",
                                              "code": "SS"}]}}],
         "name": [{"given": ["JANE"]}],
         "gender": "unknown"}
Explanation: the first two repetitions of PID-3 have no ID.

Constraints:

  • The message has exactly one PID segment. Fields after the last one present are missing, not empty.
  • Delimiters are the standard |^~\&. No escape sequences.
  • PID-7 is empty or starts with an 8-digit date YYYYMMDD; it may continue with a time and an offset.
  • urn:id: is this problem's convention. A real interface uses the URI agreed for each assigning authority.
  • Key order inside the dicts does not matter.

def padded(text: str, separator: str, size: int) -> list[str]:
    """Splits `text` and pads with "" so that indexes up to `size - 1` always exist."""
    parts = text.split(separator)
    return parts + [""] * (size - len(parts))


def without_empty(element: dict) -> dict:
    return {key: value for key, value in element.items() if value}


def to_identifier(cx: list[str]) -> dict:
    identifier = {"value": cx[0]}
    authority = cx[3].split("&")[0]
    if authority:
        identifier["system"] = "urn:id:" + authority
    if cx[4]:
        identifier["type"] = {"coding": [{"system": IDENTIFIER_TYPES, "code": cx[4]}]}
    return identifier

    pid = padded(segment, "|", 9)
    identifiers = []
    for repetition in pid[3].split("~"):
        cx = padded(repetition, "^", 5)
        if cx[0]:
            identifiers.append(to_identifier(cx))
    xpn = padded(pid[5].split("~")[0], "^", 3)
    name = without_empty({"family": xpn[0], "given": [part for part in xpn[1:3] if part]})
    born = pid[7].split("^")[0]
    return without_empty(
        {
            "resourceType": "Patient",
            "identifier": identifiers,
            "name": [name] if name else [],
            "gender": GENDERS.get(pid[8], "unknown"),
            "birthDate": f"{born[0:4]}-{born[4:6]}-{born[6:8]}" if born else "",
        }

mellp 35: Tiny FHIR Server

Medium · http · fhir · fastapi

To test the outbound side of an interface you need something to send to. A real FHIR server is a large install; a few routes in FastAPI cover what a patient feed touches. Building it also teaches the HTTP side of FHIR: which status code means what, and why a feed that retries must never create the same patient twice.

def create_app() -> fastapi.FastAPI

Each call returns a new app with its own in-memory store.

  1. POST /Patient takes a JSON object. If its resourceType is not "Patient", or it has no non-empty identifier[0].value, answer 400 with an OperationOutcome: {"resourceType": "OperationOutcome", "issue": [{"severity": "error", "code": "invalid", "diagnostics": "<why, not empty>"}]}
  2. A new identifier value creates the patient: 201, header Location: /Patient/<id>, body = the posted resource plus a server-assigned "id" (a non-empty string).
  3. An identifier value already stored replaces that patient: 200, same id, body = the new resource plus that id. Posting the same patient any number of times leaves exactly one.
  4. GET /Patient/<id> answers 200 with the stored resource, or 404 with an OperationOutcome whose issue code is "not-found".
  5. GET /Patient?identifier=<value> answers 200 with {"resourceType": "Bundle", "type": "searchset", "total": n, "entry": [{"resource": ...}]}. With no match, total is 0 and there is no entry key (no empty values, as in problem 33).

Rule 3 is not how a standard FHIR server treats POST; there, create and update are separate (PUT is the update, and PUT /Patient?identifier=... is a conditional update). Folding both into one POST keyed on the identifier makes replays from a v2 feed safe, which is what this server is for.

import fastapi
from fastapi.responses import JSONResponse


def outcome(status: int, code: str, diagnostics: str) -> JSONResponse:
    issue = {"severity": "error", "code": code, "diagnostics": diagnostics}
    return JSONResponse({"resourceType": "OperationOutcome", "issue": [issue]}, status_code=status)


def identifier_of(resource: dict) -> str | None:
    identifiers = resource.get("identifier") or [{}]
    return identifiers[0].get("value")


def create_app() -> fastapi.FastAPI:
    app = fastapi.FastAPI()
    patients: dict[str, dict] = {}  # id -> stored resource
    id_by_identifier: dict[str, str] = {}
    next_id = itertools.count(1)

    @app.post("/Patient")
    def upsert(resource: dict):
        if resource.get("resourceType") != "Patient":
            return outcome(400, "invalid", "resourceType must be Patient")
        identifier = identifier_of(resource)
        if not identifier:
            return outcome(400, "invalid", "identifier[0].value is required")
        existing = id_by_identifier.get(identifier)
        patient_id = existing or str(next(next_id))
        id_by_identifier[identifier] = patient_id
        patients[patient_id] = {**resource, "id": patient_id}
        if existing:
            return patients[patient_id]
        headers = {"Location": f"/Patient/{patient_id}"}
        return JSONResponse(patients[patient_id], status_code=201, headers=headers)

    @app.get("/Patient/{patient_id}")
    def read(patient_id: str):
        if patient_id not in patients:
            return outcome(404, "not-found", f"no Patient with id {patient_id}")
        return patients[patient_id]

    @app.get("/Patient")
    def search(identifier: str):
        found = [patients[id_by_identifier[identifier]]] if identifier in id_by_identifier else []
        bundle = {"resourceType": "Bundle", "type": "searchset", "total": len(found)}
        if found:
            bundle["entry"] = [{"resource": patient} for patient in found]
        return bundle

    return app

mellp 36: Post It

Medium · http · fhir · ack · httpx

This is the bridge between the two worlds: an HL7 v2 feed on one side, a FHIR REST API on the other. The sender of the v2 message is waiting for an ACK and knows nothing about HTTP, so every outcome of the HTTP call has to be translated into AA, AE or AR, with enough text in MSA-3 that whoever reads the error queue can tell what went wrong without the server's logs.

SUPPORTED_TYPES = {"ADT^A01", "ADT^A08"}

def forward(raw: bytes, client: httpx.Client) -> bytes

raw is an HL7 payload (UTF-8). Return the ACK payload.

  1. MSH-9.1 and MSH-9.2 joined with ^ not in SUPPORTED_TYPES -> AR, MSA-3 unsupported message type: <type>. Nothing is posted.
  2. Otherwise client.post("/Patient", json=patient) once, where patient is {"resourceType": "Patient", "identifier": [{"value": PID-3.1}], "name": [{"family": PID-5.1, "given": [PID-5.2]}]}
  3. Status 2xx -> AA, no MSA-3.
  4. Any other status -> AE, MSA-3 HTTP <status>. When the body is an OperationOutcome ("resourceType": "OperationOutcome"), append : and the diagnostics of its first issue: HTTP 400: identifier is required.
  5. httpx.TransportError (refused, timed out, connection dropped) -> AE, MSA-3 unreachable.
  6. The ACK is built as in problem 09: MSH then MSA, each ending with \r. MSH-1 and MSH-2 as in the original, MSH-3/4 = original MSH-5/6, MSH-5/6 = original MSH-3/4, MSH-7 = now as YYYYMMDDHHMMSS, MSH-9.1 = ACK, MSH-9.2 = the original trigger event, MSH-10 = a new non-empty ID on every call, MSH-11 and MSH-12 copied. MSA-1 = the code, MSA-2 = the original MSH-10, MSA-3 = the text when there is one.

Output: b"MSH|^~\\&|LAB|HOSP|EPIC|HOSP|20260105083001||ACK^A01^ACK|5c1e...|P|2.5\rMSA|AA|MSG00001\r"

import datetime
import uuid

import httpx

SUPPORTED_TYPES = {"ADT^A01", "ADT^A08"}


def build_ack(msh: list[str], code: str, text: str = "") -> bytes:
    """`msh` is the original MSH split on "|": index n holds MSH-(n+1)."""
    trigger = msh[8].split("^")[1]
    header = [
        "MSH", msh[1], msh[4], msh[5], msh[2], msh[3],
        datetime.datetime.now().strftime("%Y%m%d%H%M%S"), "",
        f"ACK^{trigger}^ACK", uuid.uuid4().hex[:20], msh[10], msh[11],
    ]
    msa = ["MSA", code, msh[9]] + ([text] if text else [])
    return ("|".join(header) + "\r" + "|".join(msa) + "\r").encode()


def error_text(response: httpx.Response) -> str:
    text = f"HTTP {response.status_code}"
    try:
        body = response.json()
    except ValueError:  # not JSON at all
        return text
    if isinstance(body, dict) and body.get("resourceType") == "OperationOutcome":
        return f"{text}: {body['issue'][0]['diagnostics']}"
    return text


def forward(raw: bytes, client: httpx.Client) -> bytes:
    segments = [line.split("|") for line in raw.decode().split("\r") if line]
    msh = segments[0]
    message_type = "^".join(msh[8].split("^")[:2])
    if message_type not in SUPPORTED_TYPES:
        return build_ack(msh, "AR", f"unsupported message type: {message_type}")
    pid = next(segment for segment in segments if segment[0] == "PID")
    family, given = pid[5].split("^")[:2]
    patient = {
        "resourceType": "Patient",
        "identifier": [{"value": pid[3].split("^")[0]}],
        "name": [{"family": family, "given": [given]}],
    }
    try:
        response = client.post("/Patient", json=patient)
    except httpx.TransportError:
        return build_ack(msh, "AE", "unreachable")
    if response.is_success:
        return build_ack(msh, "AA")
    return build_ack(msh, "AE", error_text(response))

hl7-practice 09: set_value(message, path, value) -> str

Hard

The inverse of get_value: return a new message with the value at path replaced. Same path format as problem 05.

Rules: 1. Everything else stays exactly the same. Output joins segments with \r. 2. Segment appears more than once → change the first one. 3. Field has repeats → change only the first repeat, keep the others. 4. Field/component/subcomponent doesn't exist yet → pad with empty separators up to that position. 5. def _set_nested(text: str, nums: list[int], seps: str, value: str) -> str:
    if not nums:
        return value
    parts = text.split(seps[0])
    i = nums[0] - 1
    parts += [""] * (i + 1 - len(parts))  # pad missing components/subcomponents
    parts[i] = _set_nested(parts[i], nums[1:], seps[1:], value)
    return seps[0].join(parts)


def set_value(message: str, path: str, value: str) -> str:
    segment, numbers = path.split("-")
    field_num, *sub_nums = [int(n) for n in numbers.split(".")]
    if segment == "MSH" and field_num <= 2:
        raise ValueError("MSH-1 and MSH-2 hold the separators and cannot be set")

    rows = [line.split("|") for line in message.splitlines() if line]
    row = next((r for r in rows if r[0] == segment), None)
    if row is None:
        row = [segment]
        rows.append(row)

    index = field_num - 1 if segment == "MSH" else field_num
    row += [""] * (index + 1 - len(row))  # pad missing fields

    repeats = row[index].split("~")
    repeats[0] = _set_nested(repeats[0], sub_nums, "^&", value)
    row[index] = "~".join(repeats)
    return "\r".join("|".join(r) for r in rows)

mellp 25: Route by Type

Easy · routing · python-hl7

An interface engine receives everything on one port and sends each message on to the systems that care about it. Admits go to the bed board, lab results go to the chart, and a catch-all channel keeps whatever nobody claimed. The routing key is the message type in MSH-9.

def route(raw: str, table: dict[str, T], default: T | None = None) -> T

Read the message code (MSH-9.1) and trigger event (MSH-9.2) and look them up in table, in this order:

  1. The exact type, "ADT^A01".
  2. The wildcard for the message code, "ADT^*".
  3. The catch-all "*".

Return the value of the first key that is present. If no key matches, return default when one was given, otherwise raise LookupError with the type ("ORM^O01") in its message. Table values are opaque: ports, tuples, names, anything, including values that are falsy.

Example 1:

Input:  MSH-9 = "ADT^A01^ADT_A01"
        table = {"ADT^A01": "bed-board", "ADT^*": "adt-archive", "*": "catch-all"}
Output: "bed-board"

Example 2:

Input:  MSH-9 = "ADT^A08^ADT_A01", same table
Output: "adt-archive"
Explanation: no exact key, so the wildcard for ADT applies.

Example 3:

Input:  MSH-9 = "ORM^O01^ORM_O01", table = {"ADT^*": 2575}
Output: LookupError("no route for ORM^O01")

Constraints:

  • raw is one message, segments separated by \r, starting with MSH.
  • MSH-9 always has at least the code and the trigger event. The message structure (MSH-9.3) plays no part in routing.
  • default=None means no default was given.
  • The table is not modified.

Follow-up: some routes depend on more than the type: ORU results for one facility go to a different lab system. How would you extend the table without turning it into a chain of if statements?

Hint

msg = hl7.parse(raw), then msg["MSH.F9.R1.C1"] and msg["MSH.F9.R1.C2"]. Test membership with in, not with the truthiness of table.get(key).

from typing import TypeVar

import hl7

T = TypeVar("T")


def route(raw: str, table: dict[str, T], default: T | None = None) -> T:
    message = hl7.parse(raw)
    code = message["MSH.F9.R1.C1"]
    message_type = f"{code}^{message['MSH.F9.R1.C2']}"
    for key in (message_type, f"{code}^*", "*"):
        if key in table:
            return table[key]
    if default is not None:
        return default
    raise LookupError(f"no route for {message_type}")

mellp 26: Clean It Up

Medium · transform · python-hl7

Two systems rarely agree on the details. The receiver wants its own application name in the header, names in capitals, sex coded from HL7 Table 0001, no Social Security numbers, and none of the sender's custom Z-segments. Everything else must pass through exactly as it came, because the receiver's parser is stricter than yours.

def transform(raw: str, receiving_app: str, receiving_facility: str) -> str

Return a copy of raw with these changes:

  1. MSH-5 (receiving application) and MSH-6 (receiving facility) are set to the arguments.
  2. PID-5.1 (family name) and PID-5.2 (given name) are upper-cased. Other components of PID-5 are untouched.
  3. PID-8 (administrative sex) is normalised to Table 0001, case-insensitively: M, MALE, 1 become M; F, FEMALE, 2 become F; an empty value stays empty; anything else becomes U.
  4. PID-19 (SSN) is blanked: the field stays, its value becomes empty.
  5. Segments whose name starts with Z are removed.
  6. Everything else is unchanged, character for character: segment order, the \r after every segment, MSH-2, empty fields, and the number of fields in every segment. A PID with fewer than 19 fields must not grow one.

Example 1:

Input:  MSH|^~\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|C1|P|2.5\r
        PID|1||12345^^^HOSP^MR||doe^jane^q||19800214|female\r
        ZPI|VIP|Y\r
        receiving_app="CHART", receiving_facility="EAST"
Output: MSH|^~\&|EPIC|HOSP|CHART|EAST|20260105083000||ADT^A01^ADT_A01|C1|P|2.5\r
        PID|1||12345^^^HOSP^MR||DOE^JANE^q||19800214|F\r
Explanation: the middle name stays lower-case, the PID keeps its 8 fields, the ZPI is gone.

Example 2:

Input:  PID|1||7||ROE^RICHARD||19700101|2|||||||||||123-45-6789|D1234\r  (after an MSH)
Output: PID|1||7||ROE^RICHARD||19700101|F||||||||||||D1234\r
Explanation: PID-19 is emptied, PID-20 survives.

Example 3:

Input:  MSH|...\rEVN|A08|20260105091500\r   (no PID at all)
Output: the same message with only MSH-5 and MSH-6 changed

Constraints:

  • raw is one message: segments separated by \r, the last one followed by \r. The first segment is MSH with at least 12 fields.
  • Separators are the defaults: MSH-2 is ^~\&.
  • There is at most one PID and PID-5 does not repeat. A PID may have any number of fields, or there may be none.
  • Names are ASCII.

Follow-up: the next receiver wants the same cleanup but a different sex table and keeps PID-19. How would you make the rules configuration instead of code, without writing a general-purpose mapping language?

Hint 1

The python-hl7 route: msg = hl7.parse(raw), msg.assign_field("CHART", "MSH", 1, 5), then str(msg), which ends with \r like the input. Three traps, all verified on python-hl7 0.4.5: assign_field on a field past the end of a segment appends empty fields to reach it, so blanking PID-19 grows a short PID; assigning to a component of a field that has none (PID-5 = SMITH) raises TypeError; and the segment must exist (KeyError: 'No PID segments').

Hint 2

The by-hand route: raw.split("\r"), then segment.split("|") and "|".join(...) back. Only touch indexes that exist. The trap is MSH: MSH-1 is the field separator itself, so after splitting the MSH segment on |, MSH-5 is at index 4. In every other segment, field n is at index n.

Write it in problems/26-clean-it-up/solution.py, then run:

Reference solution 
SEX_CODES = {"M": "M", "MALE": "M", "1": "M", "F": "F", "FEMALE": "F", "2": "F", "": ""}


def transform(raw: str, receiving_app: str, receiving_facility: str) -> str:
    output = []
    for segment in raw.split("\r"):
        if segment.startswith("Z"):
            continue
        fields = segment.split("|")
        if fields[0] == "MSH":
            # MSH-1 is the "|" the split consumed, so MSH-n sits at index n - 1.
            fields[4] = receiving_app
            fields[5] = receiving_facility
        elif fields[0] == "PID":
            clean_pid(fields)
        output.append("|".join(fields))
    return "\r".join(output)


def clean_pid(fields: list[str]) -> None:
    """Edits the PID fields in place, touching only fields that already exist."""
    if len(fields) > 5:
        name = fields[5].split("^")
        name[:2] = [part.upper() for part in name[:2]]
        fields[5] = "^".join(name)
    if len(fields) > 8:
        fields[8] = SEX_CODES.get(fields[8].upper(), "U")
    if len(fields) > 19:
        fields[19] = ""

hl7-practice 12: Validate header

Easy

INT-103: The engine's queue is backing up because of junk messages. Block them at the door and return a list of error codes.

validate_header(message: str, expected_version: str = "2.5.1") -> list[str]

  • First segment isn't MSH → return ["NOT_MSH"] immediately.
  • Otherwise check in exactly this order, collecting every error:
  • BAD_ENCODING: MSH-2 ≠ ^~\&
  • NO_MESSAGE_TYPE: MSH-9.1 or MSH-9.2 empty
  • NO_CONTROL_ID: MSH-10 empty
  • BAD_PROCESSING_ID: MSH-11 not one of P, T, D
  • VERSION_MISMATCH: MSH-12.1 ≠ expected_version (MSH-12 may have components, e.g. 2.4^AUS&&ISO3166_1)
  • A missing field = empty. Valid → [].

from solutions._hl7 import field, part, segments


def validate_header(message: str, expected_version: str = "2.5.1") -> list[str]:
    segs = segments(message)
    if not segs or segs[0][0] != "MSH":
        return ["NOT_MSH"]
    msh = segs[0]
    errors = []
    if field(msh, 2) != "^~\\&":
        errors.append("BAD_ENCODING")
    if not part(field(msh, 9), "^", 1) or not part(field(msh, 9), "^", 2):
        errors.append("NO_MESSAGE_TYPE")
    if not field(msh, 10):
        errors.append("NO_CONTROL_ID")
    if field(msh, 11) not in ("P", "T", "D"):
        errors.append("BAD_PROCESSING_ID")
    if part(field(msh, 12), "^", 1) != expected_version:
        errors.append("VERSION_MISMATCH")
    return errors

from solutions._hl7 import all_of, field, part


def _is_number(text: str) -> bool:
    try:
        float(text)
        return True
    except ValueError:
        return False


def validate_results(message: str, known_loinc: set[str]) -> list[str]:
    errors = []
    for obx in all_of(message, "OBX"):
        sid = field(obx, 1)
        code_field = field(obx, 3)
        if part(code_field, "^", 3) != "LN":
            errors.append(f"OBX {sid}: not LOINC")
        elif part(code_field, "^", 1) not in known_loinc:
            errors.append(f"OBX {sid}: unknown LOINC {part(code_field, '^', 1)}")
        if field(obx, 2) == "NM" and not _is_number(field(obx, 5)):
            errors.append(f"OBX {sid}: non-numeric value")
        if not field(obx, 11):
            errors.append(f"OBX {sid}: missing status")
    return errors

mellp 13: Rule Book

Medium · validation · python-hl7

Every site has its own list of things an inbound message must get right before it is allowed in: a control ID to acknowledge, a patient that can be identified, a birth date that is a real date and not in the future. A message can be perfectly legal HL7 and still fail all of them (problem 14 checks the standard's structure; this one checks one site's business rules). Report every rule a message breaks, so the sender can fix them all in one round.

def validate(raw: str, today: datetime.date | None = None) -> list[str]

Return the IDs of the violated rules, in table order, each at most once. An empty list means the message passes. today defaults to date.today(); it exists so the tests are deterministic.

ID Applies to Violated when
MSH-10 all the control ID is empty
PID all there is no PID segment (then no PID-x rule is reported)
PID-3 all no repetition of PID-3 has a non-empty ID (component 1)
PID-5 all the family name (PID-5.1) is empty
PID-7 all PID-7 is not empty, and its first 8 characters are not a real calendar date YYYYMMDD or that date is after today
PID-8 all PID-8 is not empty and not one of F M O U A N (HL7 Table 0001)
PV1 ADT^A01 there is no PV1 segment
OBX ORU^R01 there is no OBX segment

"Applies to" is matched against MSH-9.1 and MSH-9.2.

Example 1:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|MSG00001|P|2.5\r"
        "EVN|A01|20260105083000\r"
        "PID|1||12345^^^HOSP^MR||DOE^JANE^Q||19800214|F\r"
        "PV1|1|I|ICU^101^A\r"
Output: []

Example 2:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01||P|2.5\r"
        "EVN|A01|20260105083000\r"
        "PID|1||^^^HOSP^MR||^JANE||19800230|X\r"
Output: ["MSH-10", "PID-3", "PID-5", "PID-7", "PID-8", "PV1"]
Explanation: no control ID; PID-3 names an assigning authority but no ID; no family name;
             there is no 30 February; X is not in Table 0001; an admit needs a PV1.

Example 3:

Input:  "MSH|^~\\&|LAB|HOSP|EPIC|HOSP|20260105083000||ORU^R01^ORU_R01|MSG00003|P|2.5\r"
        "PID|1||~12345^^^HOSP^MR||DOE^JANE||20990101|F\r"
        "OBR|1|ORD448^EPIC|LAB7731^LAB|24323-8^Comprehensive metabolic panel^LN\r"
        today = date(2026, 1, 5)
Output: ["PID-7", "OBX"]
Explanation: the first repetition of PID-3 is empty but the second has an ID, which is fine.
             A birth date in 2099 is in the future. A result needs at least one OBX.

Constraints:

  • Segments end with \r and the message uses the default delimiters |^~\&.
  • MSH is well-formed through MSH-12. There is at most one PID, and when it is there it has fields through PID-8.
  • PID-7 and PID-8 hold a single value with no components.

Follow-up: these rules are hard-coded. A second sender needs PID-8 optional and the PV1 rule dropped. How would you turn the table into data, so one validator serves both senders?

Hint 1

Collect the segment names once ({str(segment[0]) for segment in msg} with python-hl7), then go down the table appending IDs. Put the four PID-x rules behind a single "is there a PID" check.

Hint 2

datetime.datetime.strptime(text, "%Y%m%d") raises ValueError for 19800230. In python-hl7, len(msg.segment("PID")(3)) is the number of repetitions of PID-3, and msg["PID.F3.R2.C1"] reads the ID of the second one.

import datetime

import hl7

SEXES = {"F", "M", "O", "U", "A", "N"}  # HL7 Table 0001


def validate(raw: str, today: datetime.date | None = None) -> list[str]:
    message = hl7.parse(raw)
    present = {str(segment[0]) for segment in message}
    message_type = f"{message['MSH.F9.R1.C1']}^{message['MSH.F9.R1.C2']}"
    violated = []
    if not message["MSH.F10"]:
        violated.append("MSH-10")
    if "PID" in present:
        violated += patient_rules(message, today or datetime.date.today())
    else:
        violated.append("PID")
    if message_type == "ADT^A01" and "PV1" not in present:
        violated.append("PV1")
    if message_type == "ORU^R01" and "OBX" not in present:
        violated.append("OBX")
    return violated


def patient_rules(message: hl7.Message, today: datetime.date) -> list[str]:
    violated = []
    repetitions = len(message.segment("PID")(3))
    if not any(message[f"PID.F3.R{number}.C1"] for number in range(1, repetitions + 1)):
        violated.append("PID-3")
    if not message["PID.F5.R1.C1"]:
        violated.append("PID-5")
    birth = message["PID.F7"]
    if birth and not is_past_date(birth[:8], today):
        violated.append("PID-7")
    sex = message["PID.F8"]
    if sex and sex not in SEXES:
        violated.append("PID-8")
    return violated


def is_past_date(text: str, today: datetime.date) -> bool:
    """True for a real YYYYMMDD calendar date on or before today."""
    try:
        return datetime.datetime.strptime(text, "%Y%m%d").date() <= today
    except ValueError:
        return False

mellp 14: By the Book

Easy · validation · conformance · hl7apy

Problem 13 checked one site's business rules. The HL7 standard has rules of its own: each message structure lists which segments it requires, which are optional and how often each may repeat, and each version defines its own fields and data types. hl7apy ships those definitions for every version it supports. A real interface needs both kinds of check: a message can follow the standard to the letter and still be useless to you, or carry everything you need in a shape the standard does not allow.

def conforms(raw: str) -> bool

Return True when the message is valid for its own HL7 version (MSH-12) under hl7apy's strict validation, and False otherwise, including when hl7apy cannot parse it at all.

Example 1:

Input:  "MSH|^~\\&|EPIC|HOSP|LAB|HOSP|20260105083000||ADT^A01^ADT_A01|MSG00001|P|2.5\r"
        "EVN|A01|20260105083000\r"
        "PID|1||12345^^^HOSP^MR||DOE^JANE^Q||19800214|F|||123 MAIN ST^^SPRINGFIELD^IL^62701^USA||(217)555-0142\r"
        "PV1|1|I|ICU^101^A||||1234^WELBY^MARCUS\r"
Output: True

Example 2:

Input:  the same message without its PV1
Output: False
Explanation: ADT_A01 requires a PV1. hl7apy raises ValidationError: Missing required child ADT_A01.PV1

Example 3:

Input:  a 2.5 ORU^R01 lab result with no PID segment
Output: True
Explanation: the patient group is optional in ORU_R01. Problem 13's site rules reject this message.

Message Verdict Why
admit (ADT^A01), version 2.3.1, 2.4, 2.5 or 2.5.1 True all required segments present, each once
