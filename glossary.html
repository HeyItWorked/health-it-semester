Glossary

Short definitions of terms used across the course, with the week that first explains each. In week 1 you start your own glossary.

TermMeaningWeek
ACKReply to an HL7 v2 message: AA accept, AE error, AR reject3
ADTAdmit, discharge, transfer: the HL7 v2 messages a hospital sends when a patient arrives, moves or leaves1, 3
BAABusiness associate agreement: the contract HIPAA requires before a vendor may handle PHI5
BundleA FHIR resource that holds a list of other resources, such as search results or a transaction0
C-CDAThe main US clinical-document format2
CA BaselineCanada's national starting set of FHIR profiles4
CACDICanadian Core Data for Interoperability: the list of data Canadian systems should be able to exchange4
CanaryA fake, distinctive identifier put in test data; if it shows up in a log, something leaked5
CDS HooksA standard that lets an EHR call an outside service at set moments and show its advice as cards4
ChannelIn an integration engine, one configured route: a source that receives messages and destinations that send them on6
Conditional updateA FHIR write that says “update the resource that matches this search, or create it”; the course's upsert0, 3
EHRElectronic health record: the main clinical system a hospital or clinic runs0
EMPIEnterprise master patient index: the system that works out which record numbers belong to the same person3
EncounterOne interaction between a patient and a provider: a visit, a hospital stay, a video call1
FeedThe stream of messages one system sends to another3, 6
FHIRFast Healthcare Interoperability Resources: HL7's modern standard for health data, as JSON over a REST API0, 4
HAPIOpen-source Java FHIR and HL7 v2 libraries and server0
HbA1cA blood test that reflects average blood glucose over the previous few months2
HIPAAThe US federal law that sets privacy and security rules for health information5
HL7 v2The older, pipe-delimited message standard that most hospital systems still use to talk to each other3
ICD-10Diagnosis codes used on claims and in statistics (ICD-10-CM in the US, ICD-10-CA in Canada)2
IdempotentSafe to repeat: doing it twice leaves the same state as doing it once3
Integration engineSoftware that receives each feed once and routes, transforms and retries it for every system that needs it3, 6
InterfaceA configured connection that carries one kind of message between two systems3
Interface specThe written contract between the team that sends a feed and the team that receives it6
KataA small exercise you repeat until the moves are automatic0
LOINCCodes for lab tests and observations2
MLLPMinimal Lower Layer Protocol: the small wrapper that marks where each HL7 v2 message starts and ends on a TCP connection3
MRNMedical record number, issued per facility0, 1
OCAP®First Nations principles: ownership, control, access, possession5
OIEOpen Integration Engine, the open fork of Mirth Connect6
PayerWhoever pays for care: an insurer, or a provincial health plan in Canada4
PHIProtected (US) or personal (Canada) health information5
PHIPAOntario's Personal Health Information Protection Act5
PKCEProof Key for Code Exchange: the step in an OAuth login that stops a stolen authorization code from being used4
ProfileA set of extra rules on top of base FHIR, such as required fields and allowed codes0, 4
ResourceOne FHIR record of one type, such as a Patient or an Observation0
RunbookThe step-by-step operations guide for whoever is on call6
RxNormUS normalized drug concepts2
ScopeOne permission inside an access token, such as “read this patient's Observations”4
SMART on FHIRThe standard way an app signs in to an EHR and gets permission to read a patient's FHIR data4
SNOMED CTClinical terminology for findings and procedures2
SyntheaAn open-source generator of realistic synthetic patients0
TEFCAUS national framework for health information exchange4
UCUMStandard codes for units of measure, such as mg/dL2
UpsertUpdate the record if it exists, create it if it doesn't0
US CoreThe FHIR profiles the US uses for its core data0, 4
USCDIUnited States Core Data for Interoperability: the list of data US systems must be able to exchange4
Z-segmentSite-defined HL7 v2 segment; its name starts with Z3
