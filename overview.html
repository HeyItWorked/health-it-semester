Course Overview

Before you start (prework, ~4 h)

Do these four things before week 0. The commands in the weeks assume all of them.

  1. Install the tools, then check each one. Every command below except the last should print a version number.

    docker --version     # HAPI FHIR, PostgreSQL, OIE
java -version        # 17+: Synthea, validator, Java kata
mvn -version         # Maven: Java kata (week 0)
python3 --version    # bridge and tests (weeks 3 to 6)
node --version       # 20: TypeScript kata, SMART app
dotnet --version     # .NET 8 SDK: C# kata
jq --version         # every week
socat -V             # weeks 3 and 5
pip install hl7      # gives mllp_send (weeks 3 to 6)

  2. Download two jars into the folder you will work in: synthea-with-dependencies.jar, which generates synthetic patients, and validator_cli.jar, the HL7 FHIR validator.

  3. Watch MIT Missing Semester's shell, git and development-environment lectures.

  4. Create one git repo for the whole course. A layout is suggested below.

Then start the practice server on the lab setup page to check that everything works.

How to read a week

Each week opens with a “Done when” list: the target for the week. Then comes the lecture. Type its commands yourself, in your own repo; your output should match ours except for timestamps, ids and file names. Then do the exercises. The done-when list says which ones it depends on.

Three labels recur. A session is one terminal block: the commands we typed and the output we got. A Tested note records what we actually saw, including where a tool disagreed with its specification. A Canada note says what changes in Canada.

By the end you can

New words such as FHIR, HL7 v2 and PHI are defined in the glossary, and each week introduces the ones it needs.

  • Trace an encounter and say who recorded each fact, and where it lives in FHIR.
  • Answer clinical questions in SQL and jq, and explain why two answers differ.
  • Receive HL7 v2 messages, acknowledge them only after they are safely stored, and write them to a FHIR server without creating duplicate patients.
  • Validate FHIR against US Core or CA Baseline in CI.
  • Keep PHI out of logs, prompts and git, and prove it with tests.
  • Ship a stack a reviewer can run in 10 minutes, with a runbook and an interface spec.

What you build

Suggested repo layout

health-it-semester/
  katas/        week 0: java/  csharp/  python/  typescript/
  data/         Synthea output (git-ignored, regenerated with a fixed seed)
  hl7/broken/   week 3 broken message set + expected results
  bridge/       MLLP listener, mapper, tests
  oie/          exported channel XML (week 6)
  docs/         encounter story, glossary, interface spec, runbook
  ci/           validator, PHI canary and replay checks
