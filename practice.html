Practice problems

Small test-driven exercises for weeks 3 to 6

The lectures build one project. These two problem sets drill the skills underneath it, one small function at a time: you fill in a stub and run its tests until they pass. They are optional and not counted in the ~10 h per week.

The two sets

SetSizeNeedsCovers
hl7-practice18 problems: 7 Easy, 8 Medium, 3 HardPython 3.10+, standard library onlyReading and writing messages by hand, MLLP framing, validation, routing, reconciliation, a v2 → FHIR mapping
mellp38 problems: 14 Easy, 20 Medium, 4 Hard; 2 labsPython 3.12, uv; python-hl7 from problem 06 on; Docker for Lab BFraming, ACKs, sockets, retries, a small interface engine, FHIR, TLS; a Wireshark lab and a Mirth Connect lab

hl7-practice ships with this course, in static/files/hl7-practice/. Its README.md holds all 18 specs. Problems 01 to 09 parse and build messages by hand; 10 to 18 are written as integration tickets that reuse those answers.

$ git clone https://github.com/HeyItWorked/health-it-semester.git
$ cd health-it-semester/static/files/hl7-practice
$ python3 test_practice.py             # every problem; untouched ones show "not started"
$ python3 test_practice.py p05         # one problem
$ python3 test_practice.py --solution  # the reference solutions

mellp is its own repository. Each problem is a folder with a statement, a stub and tests.

$ git clone https://github.com/HeyItWorked/mellp.git
$ cd mellp
$ uv sync
$ uv run pytest problems/01-*          # red until you fill in problems/01-wrap-it/solution.py
$ uv run pytest problems/01-* --ref    # the same tests against the reference solution

Inside a set, go in number order: later problems reuse earlier ones.

Where they fit

Do a row after its lecture section. The numbers are problem numbers in each set, and every problem appears once. Some rows go a step past the lecture: the course bridge maps patients from ADT messages, and the week 4 row maps lab results from ORU messages too.
